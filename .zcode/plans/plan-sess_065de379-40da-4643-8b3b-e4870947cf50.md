# TUI Polish Plan

The TUI has strong bones — great personality, solid two-column dashboard geometry, careful SIGWINCH/debounce handling. The kinks cluster around (a) keystroke friction in the REPL, (b) a few contrast/spacing mis-steps in the renderer, and (c) genuinely dead plumbing that actively misleads users. Changes grouped by file, lowest-risk-first.

## A. REPL keystroke friction — `src/index.ts` (the "save a click" wins)

1. **Ctrl+C respects the universal REPL contract.** Add `rl.on("SIGINT", …)`: if the line is non-empty or the suggestion menu is open, clear both and refresh the prompt; only on an *empty* line does it fall through to exit. Today, any stray Ctrl+C while typing kills the whole session — the #1 annoyance in interactive REPLs. (Node's readline emits `SIGINT` on the interface; this is the documented pattern.)
2. **Esc cancels the slash search cleanly.** Currently Esc only clears the menu, leaving `/sw` in the buffer so the next keystroke re-triggers fuzzy search. Change: when the suggestion menu is open, Esc clears the menu *and* resets `rl.line` to empty (restoring pre-`/` state — matches fzf/claude behavior). Esc with no menu open stays a no-op (won't destroy typed input).
3. **Tab accepts the top suggestion.** Tab is currently in the `navKeys` ignore-set. Wire it: if suggestions are visible, replace the line with `/<topMatch.name>` + space, close the menu, and move cursor to end. This is the single biggest tab-sequence win — users expect Tab to complete.
4. **Drop the phantom status-bar call.** Remove `hideRightStats()` at line 788 — it writes to a `stderr` row that nothing ever populates (see C.1).

## B. Visual polish — `src/tui.ts`

5. **`partial_output`: stop dimming the answer.** Streaming assistant text is the highest-value content in the UI, but it's rendered `chalk.dim` — low-contrast gray that reads as system noise. Change to normal weight (no dim). Keep the `pendingPartial` newline logic intact.
6. **`done`: preserve summary structure instead of collapsing to one line.** Today `finalText.replace(/\s+/g, " ")` smashes markdown code blocks, bullets, and paragraphs into a run-on blob — bad for a coding agent whose answer is usually structured. Drop that collapse; `wrapStreamChunk` already wraps each `\n`-delimited line independently, so newlines + the 2000-char overflow cap are preserved for free. Add one blank line of breathing room between the green `╔══╗` box and the `summary` header (currently flush).
7. **`drawBox`: fix the off-by-a-few truncation.** `slice(0, inner - 5) + "…"` produces inconsistent right margins inside error/inspect boxes. Use `slice(0, inner - 3) + "…"` so the ellipsis + padding lands exactly at the inner edge. Affects `tool_result` error boxes and `step_inspect`.
8. **`tool_call`: drop the duplicate `reasoning:` echo.** The `reasoning: <last 200 chars>` line reprints text that already streamed live via `printThinkingSnapshot`. Remove it; the dashboard's thinking panel already carries this. Keeps tool headers to a tight 2 lines (name + intent).
9. **Dashboard activity row: consistent left gutter.** `renderDashboardLines` pads the activity row as `│ ${actLine.padEnd(inner)} │` but the iter row uses `│ ` + padded + ` │` — the activity text kisses the left border. Normalize to the 2-space gutter used by the iter row.

## C. Dead code + honesty — `src/ui.ts`, `src/commands.ts`, `src/index.ts`, `AGENTS.md`

10. **Delete `src/ui.ts` entirely.** Every export is unused except `hideRightStats()` (removed in A.4), which writes to a status line nothing ever shows — it's a phantom second UI system (113 lines, its own `THEME`/`funMessages`/spinner globals that shadow the real spinner in `tui.ts`). Removes the import line in `index.ts` too.
11. **Make the queue commands honest.** The queue is *never populated* (lines run immediately; paste auto-coalesces), so `/run`/`/queue`/`/runonce` operate on an always-empty array while telling users to "type lines, then `/run`". Remove `/runonce` (provably dead — shifts from a never-filled queue, advertised in `/help`'s session group). Rewrite `/run` + `/queue` to describe the real model: single lines execute immediately, multi-line paste is auto-coalesced into one run. Update the `/help` group lists (which hardcode command names) to drop `runonce`. Touch the `/run`/`/queue` rows in `AGENTS.md`'s Key Commands table to match.
12. **Fix the dead `--no-color` ternary in `/clear`.** `state.useColor ? "\x1b[2J\x1b[H" : "\x1b[2J\x1b[H"` returns the same string both ways — collapse to the literal.

## D. Tests — `src/__tests__/tui.test.ts`

13. **`done` summary structure** — assert newlines in `event.text` survive into output (regression guard for B.6).
14. **`drawBox` margin** — assert error-box body lines all share the exact inner width (regression guard for B.7). `drawBox` isn't currently exported; export it (it's already a pure helper) so it's testable.
15. **`partial_output` weight** — extend the existing partial-output test to assert the streamed chunk is written *without* dim ANSI when `useColor:false` (guards B.5).
16. **Remove `ui.test.ts` if present** when `ui.ts` is deleted (verify it doesn't exist first — none found in exploration).

## Verification

- `npm test -- --testPathPatterns="(tui|splash|replInput)\.test"` stays green (currently 80 passing).
- Full `npm test` green; coverage thresholds (stmts 66 / branch 55 / funcs 71 / lines 67) hold — deleting uncovered `ui.ts` *raises* coverage, so the floor is safe.
- `npm run build` (tsc strict, no `as any`) clean.
- Manual: `npm run dev -- --repl`, then (a) type `/sw`, hit Esc → line clears; (b) type `/`, hit Tab → top command completes; (c) type text, hit Ctrl+C → line clears, session lives; (d) Ctrl+C on empty line → exits.

## Not changing (deliberately)

- Splash animation, spinner label rotation, dashboard geometry/SIGWINCH logic — all solid.
- The `interactiveToolApproval` `[y/N]` prompt — Enter-as-N is the correct safe default.
- Readline's own line-editing (Ctrl-A/E, history arrows) — leave to the platform.
- The 2000-char done preview cap and overflow hint — good UX, keep.

## Risk note

A.1–A.3 (keypress) aren't cleanly unit-testable without a pseudo-terminal, so they're verified by code review + the type system + manual run, not automated tests. The renderer changes (B, D) are fully covered. C.11 removes the user-facing `/runonce` command — flagging as the one behavior-surface change; it's provably unreachable today.
