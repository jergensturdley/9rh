Address code-review findings for parallelism work (c27c4fd..e181f4c)

A dedicated reviewer pass over the parallelism & efficiency merge flagged
four findings. All four were independently verified against the codebase
and with live git experiments before acting:

Fixed (review finding 1, fail-closed risk gating):
  assessToolRisk classified `echo hi > f.txt`, `cat a | tee b`, and any
  allowlisted command containing $(...) or `...` as "low", letting them
  run outside the mutation lock and land in a concurrently mutating
  call's snapshot diff. Write signals (redirection >, >>, 2>, &>, <>,
  sinks tee/sponge/dd, command substitution) now force medium, so these
  commands serialize behind the lock.

Fixed (review finding 2, git snapshot path attribution):
  `git status --porcelain` always prints repo-TOPLEVEL-relative paths,
  even when cwd is a subdirectory (verified empirically), while every
  consumer (run report, rewind, ledger) joins record paths onto
  config.workDir. When workDir sat inside a repo subdir, changes were
  attributed to `packages/app/tracked.txt` and lstat/hydration read the
  wrong paths. snapshotWorkDirForBash now resolves the toplevel via
  `git rev-parse --show-toplevel`, rekeys every porcelain path relative
  to workDir (skipping paths outside it), and threads the toplevel
  prefix into `git show :<path>` index reads, whose paths are also
  toplevel-relative. realpath normalization handles macOS /var ->
  /private/var. Also adds `--untracked-files=all` so an untracked
  directory expands to files instead of a single `dir/` entry.

Tests added (review finding 3):
  - mixed-kind diff (git vs walk snapshots) returns [] in both orders.
  - workDir-in-repo-subdir attribution: tracked edit keeps
    workDir-relative path with correct index-derived before content;
    new file in a nested subdir of workDir is detected as create.

Refuted (review finding 4, quiet-mode phantom running entries):
  Both TUI tool_call and tool_result handlers update toolHistory
  unconditionally and symmetrically (tui.ts tool_call/tool_result
  cases); getQuiet gates only thinking snapshot printing (tui.ts:1325).
  No code path can strand a "running" entry under /quiet.
